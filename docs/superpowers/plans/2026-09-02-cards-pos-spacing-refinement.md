# Cards Pos Spacing Refinement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add deliberate vertical separation to the Guest and Owner Cards Pos without changing their content, dimensions, or export behavior.

**Architecture:** Keep the existing rendered card structure and place the spacing rule in `public/cards-pos/styles.css`, where the current card rhythm already lives. Add a focused static contract in the existing Cards Pos frontend test so the spacing cannot regress while leaving `app.js`, the API, and the PDF exporter untouched.

**Tech Stack:** Static HTML, CSS, browser JavaScript, Node.js built-in test runner.

## Global Constraints

- Keep the Guest card at `108 x 175.1 mm`.
- Keep the Owner card at `108 x 290.6 mm`.
- Preserve all existing copy, editable fields, images, proportions, and PDF export behavior.
- Adjust CSS spacing only, reusing the existing card structure and tokens where they already express the intended rhythm.
- No JavaScript, API, database, authentication, history, save-flow, typography, card dimension, content, asset, dependency, or layout-abstraction changes.
- Run `node --test tests/unit/pos-cards-frontend.test.mjs`, `npm run verify`, and `git diff --check`.
